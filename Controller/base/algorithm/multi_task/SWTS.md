# SWTS 算法核心思路整理

## 🔍 一、算法总体概述

**SWTS（Spark Workflow Task Scheduling）** 是一种面向**异构 Spark 集群**的**多级工作流任务调度算法**。其核心思想是通过**三层调度框架**（作业-阶段-任务）结合**动态反馈机制**，在**DAG约束**和**节点性能异构**的双重挑战下，实现**最小化工作流完成时间（Makespan）** 的目标，同时兼顾**负载均衡**和**资源利用率**。

---

## 🏗️ 二、三层调度架构

SWTS 在原生 Spark 架构基础上，扩展了三个核心调度组件：

### 1. **DAG-based Job Scheduler (DJS)**
- **职责**：对工作流中的多个作业进行**拓扑排序调度**
- **输入**：整个工作流的 DAG（作业间依赖关系）
- **核心策略**：不采用随机的拓扑顺序，而是根据数据中心平均性能生成**优化后的作业执行顺序**
- **输出**：作业的调度序列，提交给 DSS

### 2. **DAG-based Stage Scheduler (DSS)**
- **职责**：对单个作业内的多个阶段进行**细粒度调度**
- **输入**：单个作业的 DAG（阶段间依赖关系）
- **核心策略**：基于资源异构性生成阶段的**执行优先级顺序**
- **输出**：阶段的执行顺序，提交给 NTS

### 3. **Node-aware Task Scheduler (NTS)**
- **职责**：将阶段内的任务分配到具体执行器节点
- **核心策略**：考虑**负载均衡**，避免某些节点过载而其他节点闲置
- **独特功能**：节点感知，动态调整任务分配

```
工作流程：
DJS → (作业顺序) → DSS → (阶段顺序) → NTS → (任务分配) → 执行节点
```

## ⚡ 三、核心调度策略

### 1. **多级节点分类（Multi-level Node Classification）**
- 根据节点**负载状态**将异构节点分组
- 动态监测节点性能（CPU利用率、内存使用率、I/O等待）
- 实时更新节点分类，适应负载变化

### 2. **推测性阶段执行（Speculative Stage Execution）**
- 监测执行缓慢的任务
- 在空闲节点上创建**任务副本**
- 以最早完成的任务副本为准，避免“慢任务”拖累整体进度

### 3. **节点感知策略（Node Awareness Strategy）**
- 实时评估节点性能、负载变化、执行时间
- 基于反馈动态调整任务分配
- **公式**：节点容量评估
  ```
  C_node = α(1 - U_cpu) + β M_free + γ(1 - W_io)
  其中 α=0.5, β=0.3, γ=0.2
  ```

### 4. **集群节点分组（Cluster-based Node Division, CND）**
- 基于节点相似性（处理能力、内存、网络）动态聚类
- **目标**：增强组内一致性，保持组间隔离
- **动态调整**：根据聚类质量（组内距离 vs 组间距离）调整分组数量

## 📊 四、调度决策机制

### 1. **作业优先级计算**
作业 J_i 的优先级由三个因素决定：
```
Priority(J_i) = α·CPL(J_i) + β·TPS(J_i) + γ·DLS(J_i)
```
- **CPL（关键路径长度）**：作业完成的最短时间
- **TPS（任务并行度评分）**：作业的并行执行潜力
- **DLS（数据局部性评分）**：数据传输延迟的度量

### 2. **阶段调度决策**
- 使用**阶段等待队列（SWQ）** 和**阶段执行队列（SEQ）**
- 基于优先级对阶段排序
- 优先调度**关键路径**上的阶段
- 考虑**数据局部性**选择节点组

### 3. **任务分配逻辑**
- 动态计算每个节点的**执行阈值**
- 将高优先级任务分配给高容量节点
- 若节点负载超过阈值，将多余任务重新分配到其他节点
- 采用**迭代优化**调整任务分布

---

## 🔄 五、动态调整机制

### 1. **调整方法（Adjustment Method, AM）**
- **输入**：初始调度方案 R，槽位集合 S
- **过程**：
  1. 找到完成时间最晚的节点 u
  2. 找到完成时间最早且可调整的节点 v
  3. 应用局部搜索优化调度方案
  4. 重复直到没有进一步改进
- **输出**：优化后的调度方案 R'

### 2. **反馈循环**
```
执行监测 → 性能评估 → 调度调整 → 重新分配
    ↑                                   ↓
    └────────────────────────────────────┘
```

## ⏱️ 六、时间复杂度分析

SWTS 的总体时间复杂度为：
```
O(V + E + V log V + I₁N² + T log T + NT + I₂T)
```
其中：
- V, E：工作流 DAG 的节点数和边数
- N：计算节点数
- T：任务总数
- I₁, I₂：迭代次数

对于大规模工作流（T ≫ V, E），主导项为：
```
O(I₁N² + T log T)
```

## 🎯 七、与现有方法的对比优势

| 对比维度 | 传统方法（Rainbow, SAF, DSWTS） | SWTS 创新点 |
|---------|--------------------------------|-------------|
| **调度层次** | 单级（作业或阶段）独立优化 | **多级联合优化**（作业+阶段+任务） |
| **动态性** | 静态或半动态，无法运行时调整 | **实时反馈调整**，支持运行时重调度 |
| **异构性利用** | 假设同构或静态分组 | **显式利用异构性**，动态节点分组 |
| **负载均衡** | 简单负载分配，易产生不均衡 | **节点感知+动态再平衡** |
| **任务执行** | 无慢任务处理机制 | **推测性执行**避免慢任务阻塞 |

## 📈 八、性能表现（论文数据）

与 Rainbow、SAF、DSWTS 相比，SWTS 在实验中表现：
- **Makespan 减少**：高达 40%
- **负载均衡改善**：55%
- **资源利用率提升**：20%

## 🧩 九、可提取的核心思想（适合你的框架）

1. **多级调度思想**：将全局优化分解为作业→阶段→任务的层级决策
2. **动态反馈机制**：基于实时监控调整调度决策
3. **节点感知分组**：显式利用异构性，避免“一刀切”的资源分配
4. **关键路径优先**：优先调度影响整体完成时间的任务
5. **推测性执行**：对慢任务创建副本，提高容错性和性能

## 💡 十、在你的框架中的应用建议

如果你要在 **CES-Multi** 中借鉴 SWTS 思想：

1. **引入多层决策**：
   ```
   作业选择（滚动窗口）→ 作业内任务调度（考虑依赖）→ 节点级分配
   ```

2. **增加动态调整模块**：
   - 监控节点实时负载
   - 对运行中的作业进行微调（如任务迁移）

3. **实施节点分组策略**：
   - 基于 CPU/内存/带宽能力将边缘节点聚类
   - 不同组分配不同类型的作业

4. **关键路径分析**：
   - 识别作业内部的依赖关键路径
   - 优先保证关键路径上任务的资源需求

|------|----------------|

| **目标** | 最小化 Makespan + 负载均衡 + 高资源利用率 |
| **异构处理** | 节点分类 + 动态分组 + 节点感知调度 |

| **DAG处理** | 关键路径优先 + 拓扑优化 |
| **复杂度** | 多项式时间，可扩展到大工作流 |
