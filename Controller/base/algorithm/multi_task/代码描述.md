# 多作业队列在线调度扩展方案（与实现对齐）

## 一、目的与实现映射

本文档描述的模型与原型实现位于 [Controller/base/algorithm/multi_task](Controller/base/algorithm/multi_task)。为避免理解偏差，本版本已与当前实现代码对齐，补充了实现细节（窗口选择、评分函数、映射策略、新启发式代理集成、仿真器统计项等）。

核心目标保持不变：在边缘节点的CPU、内存、链路带宽约束下，平衡三项指标：
- **带宽满足度**（优先）
- **系统负载均衡度**（节点/链路利用的分布均衡）
- **作业平均等待时间**（包含未开始作业的截止等待统计）


## 二、实现中使用的关键约定（代码现状）

- 物理网络用 `PhysicalNetwork` 表示，包含 `nodes`（`PhysicalNode`）和双向 `links`（`PhysicalLink`）。
- 节点资源：`cpu_total` / `ram_total`，运行时维护 `cpu_free` / `ram_free`，分配/释放使用 `allocate`/`release`。
- 链路资源：`bw_total` / `bw_free`，按路径逐跳分配带宽。
- 作业映射时，节点资源按作业任务数均摊分配（每个虚拟任务分配 `job.cpu / job.task_count`、`job.ram / job.task_count`）。
- 作业元信息中可包含 `metadata['use_new_heuristic']` 标志，触发对外部启发式（`PPO_my`）映射尝试。


## 三、调度器与评分（代码实现要点）

实现提供了多种调度器工厂函数，返回可用于仿真的闭包：

- `make_fifo_scheduler()` / `fifo_scheduler`: 队列头优先（返回索引 0）。
- `make_sjf_scheduler()` / `sjf_scheduler`: 按 `job.length` 最短优先。
- `make_random_scheduler()`: 随机选择队列内作业索引。
- `make_priority_scheduler()`: 按 `job.priority` 最大选择。
- `make_ces_scheduler(network, max_load_factor=1.0, theta=5.0)`: 文档中 CES 的实现版本（代码已实现，细节如下）。
- `make_swts_scheduler(network)`: 简化版 SWTS 启发式实现（CPL/TPS/DLS/资源匹配组合得分）。
- `make_adaevo_scheduler(network, tau=50.0, K=3)`: 简化的 AdaEvo 风格实现（按紧急度分组，再在组内评分）。

CES（实现要点）：

- 窗口选择：W = min(int(max_load_factor * number_of_physical_nodes), len(queue))，候选集为 `queue.jobs[:W]`（即队列前 W 个作业）。
- 资源适配度计算：对 CPU/RAM/BW 分别计算 match := min(1.0, max_free / demand)，其中 `max_free` 为网络中对应资源的最大空闲值（节点或链路的最大 `*_free`），最终 S_res = 平均值。
- 等待因子：S_wait = 1 - exp(- wait_time / theta)（实现中使用近似 e=2.718281828）。
- 综合评分：S_total = 0.6*S_res + 0.3*(priority/5.0) + 0.1*S_wait。
- 返回值：闭包返回候选子集内（相对于队列的）得分最高的作业索引。

SWTS / AdaEvo（实现要点）：

- SWTS 用 `run_time`、`task_count`、带宽需求与当前网络空闲资源构造启发式评分，权重在实现中为固定组合。
- AdaEvo 实现按优先级/等待时间计算“紧急度”，取前若干紧急作业为候选，再按资源匹配 + 作业内部指标评分，并以紧急度作为放大因子。


## 四、作业映射与带宽分配（Simulator 实现细节）

映射流程在 `Simulator.try_map_job` 中：

1. 若 `job.metadata.get('use_new_heuristic')`：调用 `try_map_job_with_new_heuristic(job)`。
   - 该函数会尝试动态加载 `PPO_my` 目录下的模块（路径候选包含若干相对/绝对路径），优先尝试使用已保存的 PPO 检查点与 `SimpleSequentialAgent` 执行一次 greedy episode；若不可用或失败，则回退到 `create_heuristic_agent` + `run_heuristic_episode`。
   - 映射结果会尝试解析为 `mapping`（ vnode_idx -> physical_idx/name ）以及 `final_bandwidth` 列表，若无法解析则抛出异常并回退或视为失败。

2. 回退贪心映射（默认路径）：随机打乱物理节点顺序，然后为每个任务顺序找到一个能分配均摊 CPU/RAM 的节点（若某任务无法放置则回滚并返回失败）。

3. 带宽分配（贪心映射实现与限制）：
   - 简化实现仅在至少两个分配节点时为第一对分配 `bw_req = max(job.bw_min, 0.0)`，路径为两节点间的最短路径；若路径任一链路 `bw_free < bw_req` 则回滚并认为映射失败。
   - 在 `try_map_job_with_new_heuristic` 中，如果外部启发式返回 `final_bandwidth` 列表，会按虚拟链路顺序尝试为每条虚拟链路分配对应带宽（沿 shortest path），否则使用 `job.bw_min`。

4. 映射成功后：记录 `job.assigned_nodes`、`job.allocated_paths`（存储为 (path_links, bw)）与 `job.bw_alloc`（累计已分配带宽）。

5. 释放资源：`release_job_resources` 支持兼容多种 `allocated_paths` 格式并按均摊释放节点资源与沿路径释放带宽。


## 五、仿真器统计与指标（实现当前行为）

- 仿真器在每个 `step()` 收集并记录历史字典（`self.history`），包含：
  - `time`, `completed`, `avg_waiting`（针对所有已到达作业，截至当前时间的平均等待：若已开始使用 start_time，否则用 now-arrival），`avg_waiting_completed`（仅已完成作业原有统计），
  - `avg_bw_satisfaction`（对已完成作业：若所有虚拟节点映射到同一物理节点则计为 1.0，否则为 min(1.0, bw_alloc / bw_max)），
  - `avg_cpu_util`, `avg_bw_util`, `L_cpu`, `L_ram`, `L_bw`, `load_balance`。

- 负载均衡度 `load_balance` 的权重可由 `sim_config.LOAD_BALANCE_WEIGHTS` 配置，否则采用默认 `{w1_cpu:0.4,w2_ram:0.4,w3_bw:0.2}`。

- `Simulator.metrics()` 返回与历史一致的汇总项：包括 `avg_waiting`（同 `avg_waiting` 含义：对已到达作业截止当前的平均等待）与 `avg_bw_satisfaction` 等。


## 六、与文档原先模型的差异（要点总结）

- 窗口选择：实现中窗口是基于物理节点数与参数 `max_load_factor` 的有限整数 `W = min(int(max_load_factor * |nodes|), len(queue))`，候选为队列前 W 个作业，而非基于复杂负载比例公式的动态 floor 计算（代码中提供了可调整的 `max_load_factor` 参数）。
- 资源匹配：实现用网络中单个资源类型的“最大空闲值”作为归一化分母（`max_cpu_free` / `max_ram_free` / `max_bw_free`），而不是全网平均或更复杂的归一化量。
- 带宽分配：贪心路径带宽分配实现较为保守（仅为首对节点分配 `bw_min`），而对启发式（PPO_my）映射结果会尝试按 `final_bandwidth` 列表逐对分配。
- 等待时间统计：实现将 `avg_waiting` 从仅完成作业的平均等待，改为对“所有已到达作业（包含未开始）截至当前时间的等待”进行统计；同时保留 `avg_waiting_completed` 以兼容历史统计。
- 新增兼容性处理：`try_map_job_with_new_heuristic` 尝试多路径加载外部模块、检查点容错加载，并在失败时回退到启发式代理，日志中保留丰富的调试输出以便调查。


## 七、建议（基于实现）

- 如果希望文档中的数学表达严格映射到实现，请考虑：
  - 将窗口动态公式替换为实现中的 `W = min(int(max_load_factor * |P|), |Q_wait|)` 或在实现中引入文档中的动态窗口公式。 
  - 将资源匹配中的归一化从“最大空闲值”替换为“全网最大可用/平均可用”以更贴合数学模型（或在文档中注明实现采用的简化归一化）。
  - 明确记录带宽分配的简化假设：贪心策略只为第一对节点分配 `bw_min`，更复杂的虚拟链路逐一映射需依赖外部启发式代理的 `final_bandwidth` 输出。
